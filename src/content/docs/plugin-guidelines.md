插件跑在别人的主控里，能看到用户、套餐、订阅这些敏感数据，前端代码以管理员身份运行。下面的约定是为了让管理员敢装、装了不出事。字段和接口细节见 [插件参考](/docs/plugin-reference)。

## 命名与版本

- **插件 id 定了就别改**：数据、设置、开发令牌、已装实例都按 id 记，改 id 等于换了一个插件。用能看出用途的英文短词，如 `epay`、`unlock-check`、`monthly-income`，不要用 `test`、`plugin1`。
- **版本号用语义化版本**：修 bug 加第三位（1.2.**3**），加功能加第二位（1.**3**.0），不兼容的改动（删设置项、改接口返回结构、要新权限）加第一位。预发布用 `1.3.0-beta.1`。
- **每次发布都要改版本号**，并在说明里写清楚改了什么。
- `name` 写中文名，同时给 `name_en`；页面也同时给 `title` 和 `title_en`。

## 权限最小化

- **只申请真的用得到的权限**。管理员启用时会逐条看到；多一条无关的权限就少一分信任。
- `http:fetch` 写**具体域名**，能写 `api.example.com` 就别写 `*.example.com`。
- 能用只读权限就别用写权限；能用 `routes:admin` 就别开 `routes:public`。
- 加新权限会让已安装的插件停用、等管理员重新确认——这是故意的。在版本说明里解释为什么需要它。

## 安全

**公开接口（`routes:public`）**

- 默认当成会被任何人访问：**一定要验签或校验来源**（例如收款回调校验支付平台的签名），不要只看参数。
- 回调要幂等：同一笔订单回调两次只处理一次（用 `mmwx.kv` 记已处理的订单号）。
- 不要在公开接口里返回用户名单、订阅地址、内部 id 之类的信息。

**密钥**

- 密钥、令牌放**设置项**，并标 `"format": "password"`：面板遮罩显示，日志里也看不到。
- 不要把密钥写死在代码里，也不要放进前端——前端代码谁都能下载。
- 需要调第三方接口的事情放后端做，前端只调插件自己的后端。

**输入与输出**

- 不信任任何输入：`req.query`、`req.body`、事件数据都要校验类型和范围。
- 前端渲染用户数据用 React 正常插值，**不要用 `dangerouslySetInnerHTML`**。
- 订阅过滤器改的是所有人的订阅，只改你要改的部分，改完的配置要能被客户端正常加载；出错时返回 `null`（不改）而不是半成品。

**数据**

- 只存需要的数据；用户删除、插件卸载后不该留下的东西不要放到插件外面。
- 卸载插件会删掉它的全部数据和设置，这一点在说明里讲清楚。

## 性能

- **接口要快**：10 秒超时，但用户等不了这么久。慢的事情放定时任务里做，接口只读结果。
- **订阅过滤器限时 300 毫秒**，每次拉订阅都会跑，不要在里面调外部网址。
- **定时任务要幂等、能补跑**：上一次没跑完，这一次会跳过；主控重启会错过若干次。不要假设「每分钟一定执行一次」。
- **`mmwx.kv` 不是数据库**：单值 ≤ 256 KB、总量 ≤ 5 MB。存汇总和状态，不要存流水；需要列表时用前缀分键（`order:2026-11-20:xxx`）并定期清理。
- `http.fetch` 每分钟 120 次，批量调用要合并或缓存。
- 连续出错 5 次插件会被自动停用：可预见的失败（外部接口超时、参数不对）要自己 `try/catch` 并返回明确的错误，别让异常一路抛上去。

## 界面

- 用 SDK 的 `ui.*` 组件和面板的 Tailwind 类名，界面会自动跟着面板主题、深浅色、圆角走。
- **自定义 CSS 一律加插件前缀**（如 `.plugin-epay-xxx`），不要写 `body`、`button` 这类全局选择器，不要改面板自己的类。
- 手机宽度（375px）下要能用：表格可横向滚动、按钮不挤出屏幕。
- 首页卡片要轻：尽量用 `size: 'third'`，加载时显示骨架（`ui.Skeleton`），失败时给一句人话而不是空白。
- 行按钮、工具栏按钮的 `label` 要短（4–6 个字），用 `icon` 辅助。
- 危险操作（删除、改密码、扣费）先 `confirm()`，并写清楚后果。

## 多语言

- 界面上的字都放 `locales/zh-CN.json` 和 `locales/en.json`，两份的 key 要一致。
- 文案用 `useT()` / `ctx.t()` 取，数量、名字等用 `{{变量}}` 插值，不要拼字符串。
- `plugin.json` 里的 `name_en`、页面 `title_en`、设置项 `title_en` 都要填。

## 日志

- 日志给管理员排查问题用：写清楚「在做什么、结果怎样」，如 `订单 123 回调验签失败:签名不匹配`。
- **不要打印密钥、令牌、密码、完整订阅地址**。
- 不要在高频路径（每次请求、每次过滤器）打 info 日志；每个插件只保留最近 1000 条，刷屏会把有用的挤掉。
- 用 `mmwx.log.warn / error` 区分级别。

## 兼容性

- 用到新版主控才有的能力时，在 `plugin.json` 里写 `minMaster`，低版本主控会拒绝安装而不是装上了用不了。
- 宿主接口的返回值与开放 API 同结构（例如 `mmwx.packages.list()` 返回 `{ packages: [...] }`），取字段时做好缺省处理。
- 插槽给的行数据只有固定的几个字段，别依赖面板内部的其它字段。
- 后端脚本是单文件、没有模块系统：用到的第三方库请在打包时内联，并确认它不依赖 Node 或浏览器专有的 API。

## 发布前检查清单

- [ ] `version` 已经加过，说明里写了改动
- [ ] 权限是最少的；新增权限在说明里解释了
- [ ] 公开接口都验签、幂等
- [ ] 密钥都在 `format: password` 的设置项里，代码和前端里没有
- [ ] 中英文案齐全，`name_en`、`title_en` 已填
- [ ] 手机宽度下看过，深色模式下看过
- [ ] 不带 `--inspect`（在主控里运行）完整跑过一遍
- [ ] 日志里没有敏感信息
- [ ] 卸载后再装一次，能正常工作
- [ ] 用 `mmwx-plugin pack` 打的包，在一台干净的测试主控上装过
