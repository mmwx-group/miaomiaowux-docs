只配主控域名时，普通用户能从三个地方拿到主控地址：

- **扫码登录**：二维码 / 登录链接里的 `host` 就是主控域名。
- **拉订阅**：官方客户端拉订阅时，应答里带着实时通道地址（`mmwx-realtime-url`），也是主控域名。
- **订阅域名上打开面板**：开了「关闭公网访问」时，会被跳转到主控域名。

配好独立的 [订阅域名](/docs/domain-subscription) 后（主控 v0.6.4-beta.3 起），这三处都改成订阅域名，普通用户从头到尾只接触订阅域名。管理员不受影响，仍然用主控域名。

## 效果

| 场景 | 普通用户 | 管理员 |
| --- | --- | --- |
| 扫码登录、「登录客户端」、「复制登录链接」 | 订阅域名 | 主控域名 |
| 客户端账号登录（手动填地址） | 填订阅域名即可 | 填主控域名 |
| 订阅应答里的实时通道地址 | 订阅域名 | 订阅域名 |
| 在订阅域名上打开面板或其它非订阅路径 | 404，不跳转 | 404，不跳转 |

打开了 [用户入口](/docs/domain-user-portal) 时，普通用户连网页面板也在订阅域名上用，主控域名可以完全不发给用户；再打开「禁止普通用户在主控域名登录」，普通用户就只能从订阅域名登录。

## 前提

1. **配置了订阅域名，且与主控域名不同**：系统设置 →「系统」→「订阅域名」。
2. **订阅域名能提供客户端加密接口**：`/api/secure/cert`、`/api/secure/rpc`、`/api/secure/ws`（WebSocket）三条都要能从外网经订阅域名的 443 端口到达主控。
   - 订阅域名的 Nginx 是主控自动配置的：在订阅域名的 HTTPS 反代卡片里点 **重新配置 Nginx**（旧版本生成的配置没有放行这三条，卡片会提示「Nginx 配置与当前开关不一致」）。
   - 自己维护的 Nginx / Caddy / Cloudflare 规则：照 [订阅域名 · 手动配置](/docs/domain-subscription#手动配置) 补上。
3. **激活了许可证**：客户端证书由许可证服务按域名签发。订阅域名和主控域名各有一张证书，用的是两把不同的密钥，客户端从证书里看不出两个域名属于同一台主控。

### 什么时候生效

主控会从外面把订阅域名上的三条接口都请求一遍，**全部能用才切换**，之后每 10 分钟复查一次：

- 不通时普通用户照旧拿到主控域名（扫码登录不会因此坏掉），[检查](#在面板里检查) 会说明原因。
- 主控重启后、还没探测出结果的头几秒，订阅应答里暂时不带实时通道地址（客户端下次拉订阅时会拿到），不会退回主控域名。

## 部署要求

只改面板设置还不够。下面三条任何一条没做到，主控地址都能从订阅域名上查出来：

| 要求 | 原因 | 怎么做 |
| --- | --- | --- |
| 订阅域名**不能解析到主控的 IP** | 解析结果就是主控 IP，知道 IP 也就找到了主控 | 给订阅域名开 CDN 代理（如 Cloudflare 橙色云），或者放一台前置机反代回主控 |
| 订阅域名**用不同的主域名** | 证书透明度日志（如 crt.sh）按主域名就能列出所有签过证书的子域名：用 `sub.example.com` 一查，`panel.example.com` 也在里面 | 例如主控用 `panel.example.com`，订阅用 `sub.another.net` |
| 订阅域名**单独一张证书** | TLS 握手时证书内容是公开的：覆盖主控的泛域名证书（`*.example.com`）或同时写了主控域名的多域名证书，一连就能看到 | 在 [证书管理](/docs/certificates) 里给订阅域名单独申请证书 |

:::tip[放心走 CDN]
客户端和主控之间在 HTTPS 之外还有一层端到端加密，CDN 在中间也看不到扫码登录、账号密码和实时推送的内容。用 Cloudflare 时保持 WebSocket 开启（默认开），SSL/TLS 模式选「完全」。
:::

用前置机反代时，转发到主控要**保留 Host 为订阅域名**：主控按 Host 认出订阅域名，给出对应的证书、放行对应的路径。

## 在面板里检查

系统设置 →「系统」→ **隐藏主控地址检查** → 点 **开始检查**。检查会从主控向外发请求（探测订阅域名、查本机公网 IP），所以要手动点，不会随页面自动运行。

第一行显示当前状态：

- **生效中**：普通用户扫码登录与实时通道已经在用订阅域名。
- **未生效**：普通用户仍在用主控域名，看下面哪一项没通过。

| 检查项 | 没通过时 |
| --- | --- |
| 独立订阅域名 | 订阅域名没填、填的是 IP，或与主控域名相同 |
| 订阅域名提供客户端加密接口 | 三条接口有一条不通，提示里写着是哪一条、返回了什么，处理见 [常见问题](#常见问题) |
| 与主控不同主域名 | 两者同属一个主域名（警告） |
| 订阅域名不解析到主控 IP | 订阅域名解析到了主控的公网 IP |
| 订阅域名证书不含主控域名 | 订阅域名 443 端口上的证书能覆盖主控域名 |

## 登录客户端

- **普通用户**：在网页面板右上角头像 →「扫码登录手机」，二维码里已经是订阅域名，直接扫；账号登录时「主控地址」填订阅域名，例如 `https://sub.another.net`。
- **管理员**：二维码里是主控域名；账号登录填主控域名。开了用户入口时，管理员在订阅域名上登录不了（和网页一样，回复与密码错误相同）。

各种登录方式的细节见 [客户端登录](/docs/client-login)。

## 仍然可能暴露主控的地方

- **TG Mini App**：只有打开 [用户入口](/docs/domain-user-portal) 时，用户页才搬到订阅域名；否则 Mini App 仍从主控域名打开。
- **普通用户在主控域名登录网页**：发给用户的是主控地址，他自然知道。改用用户入口，并打开「禁止普通用户在主控域名登录」。
- **节点和主控在同一台机器**：节点地址就是这台机器的 IP，订阅内容里本来就有它。想彻底分开，主控不要兼做节点。

## 常见问题

### 检查提示「返回 HTTP 404：订阅域名的反代没有放行 /api/secure/*」

反代只转发了订阅路径。主控自动配置的 Nginx 点 **重新配置 Nginx**；自己写的规则照 [订阅域名 · 手动配置](/docs/domain-subscription#手动配置) 补上三条接口，`/api/secure/ws` 要转发 WebSocket（`Upgrade` / `Connection` 头）。

### 检查提示「返回 HTTP 503：…too many requests」

许可证服务暂时限流（例如主控刚连续重启过几次），证书没签出来。等一两分钟再点「重新检查」。

### 检查提示「返回的证书不是本主控订阅域名那套」

订阅域名的反代转发到了别的主控，或者 CDN 回源地址不是这台主控。改正回源后重新检查。

### 改完设置后普通用户还是拿到主控域名

切换要等探测通过：点一次「重新检查」会立即重新探测。已经生成的旧二维码不会变，关掉窗口重新生成即可。
