## Overview

A package defines the traffic quota, validity and node scope a user can use. One user can hold several package instances; each has independent credentials, cycle baseline, quota and expiry.

## Package attributes

| Attribute                    | Description                                                            |
| ---------------------------- | ---------------------------------------------------------------------- |
| Name / description           | Display name and notes                                                 |
| Traffic quota                | GB per cycle, 0 = unlimited                                            |
| Counting mode                | One-way (×1, default) or two-way (×2)                                  |
| Clash / Surge / Loon template | Templates used when generating subscriptions; empty = system default |
| Billing cycle                | Days, default 30; optional monthly reset on a given day                |
| Speed limit (Mbps)           | Max download per user, 0 = unlimited (PRO, embedded Xray)              |
| Connection limit             | Max concurrent connections per user, 0 = unlimited (PRO)               |
| Forwarding quota             | Lets package users create their own forwards on selected entry chains  |
| Associated nodes             | Node scope; none = all nodes; optional per-package node names          |

## Create a package

1. Open "Packages"
2. Click "Create Package Template"
3. Enter name, description, quota; choose counting mode and templates as needed
4. Set the cycle / reset day, speed limit and connection limit
5. Tick the nodes on the right (none = all nodes)
6. Click "Save"

## Publish carpool

"Publish carpool / Unpublish" lists the package on the carpool market so other users can join with an invite code, see [Carpool FAQ](/docs/en/faq-carpool).

## Speed and device limits

Packages can set a speed limit (Mbps) and a connection cap; users can also get individual overrides in User Management (user level overrides package level).

### Speed limit

Upper bound in Mbps, 0 = unlimited. Enforced by the Agent-side limiter on the user's connections; the UI shows the conversion (8 Mbps ≈ 1 MB/s, 100 Mbps ≈ 12.5 MB/s).

### Connections

Caps concurrent connections per user. This is "connections", not "devices" — one device easily opens dozens of connections; recommended values: [Rate Limiting](/docs/en/node-ratelimit).

### Auto throttle / release

Optional automatic throttling: when a user exceeds the quota they are slowed down instead of cut off, and released after the monthly reset or a quota top-up.

## Traffic statistics and billing multipliers

The Xray traffic collector counts every user's traffic in real time. When billable traffic exceeds the quota the subscription stops returning nodes (or throttles, per the setting above).

- Raw up/down are stored per Xray user/email and weighted at collection time
- Packages choose one-way (`oneway`, `×1`) or two-way (`twoway`, `×2`)
- Billable = (raw up + raw down) × package direction multiplier × node multiplier
- Multiplier changes only affect later increments; each instance advances its baseline per its reset settings, admins can reset manually

The admin home shows server billing figures; the user home and the user list show user Xray billing traffic. With multiple packages the list aggregates all credentials while the limit comes from the primary package — check instances in "Manage Packages".
