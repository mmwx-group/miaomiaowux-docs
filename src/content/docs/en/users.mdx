## Overview

The user module manages subscriber accounts, permissions and subscription tokens. Two roles exist: administrator and regular user. Search by username / nickname / package above the list or filter by package; "Full view / Renewal view" at the top right switches the list layout.

## Roles

| Role          | Permissions | Description                                          |
| ------------- | ----------- | ---------------------------------------------------- |
| Administrator | All         | System, server and user management                   |
| Regular user  | Subscribe   | View own subscription link and profile               |

## Create a user

1. Open "Users"
2. Click "Add User"
3. Enter the username; email / nickname / remark are optional
4. The initial password is random by default and can be changed before creating
5. Click "Create"; the initial password is copied to the clipboard
6. The user short code and subscription token are generated; use "Copy subscription" in the list

## Bind and manage packages

Rows without a package show a "Bind Package" button; for bound users open the "…" menu and click the package name to reach "Manage Packages":

![Manage packages dialog screenshot](../../../assets/screenshots/users-manage-packages-dialog.webp)

Manage packages: bound package cards (usage / expiry / unbind), package picker, expiry (+30 / +60 / +90 days), monthly reset, traffic override

| Item                     | Description                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Bound packages           | One card per package instance with used / limit and expiry; unbind individually                              |
| Choose package           | Pick from the created package templates                                                                      |
| Expiry                   | +30 / +60 / +90 days or a date; on expiry all inbound configs are removed and the package unbound            |
| Monthly traffic reset    | Reset on the given day (1–31)                                                                                |
| Traffic override (GB)    | User override > package quota; 0 = explicitly unlimited, empty = package default; cleared on package change  |
| Add as separate package  | One user can hold several packages; the same node gets independent sub-accounts with separate traffic, connections and expiry |

### Example: a 30-day Advanced package for a friend

1. "Add User" → username `alice`, remark "friend", create (the initial password is copied, send it over)
2. On alice's row click "Bind Package" → choose "Advanced" → "+30 days" → "Save package"
3. The "Package/Traffic" column shows a bar; click "Copy subscription" and send the link
4. Before expiry click +30 days again in "Renewal view" or the "Renew" menu item

## Action menu

The "…" at the far right of each row:

![User action menu screenshot](../../../assets/screenshots/users-row-menu.webp)

Action menu: reset password, reset traffic, manage packages (shows the current package name), renew, rate limit, sub-accounts, nodes, delete

| Item            | Description                                                                                                       |
| --------------- | ----------------------------------------------------------------------------------------------------------------- |
| Reset password  | Generates a new random password (editable) and applies it on confirm                                              |
| Reset traffic   | Zero the user's usage for the current period                                                                      |
| Package name    | Opens "Manage Packages"                                                                                           |
| Renew           | +30 / +60 / +90 days                                                                                              |
| Rate limit      | Per-user speed / connection overrides with priority over the package, plus per-node overrides, see [Rate Limiting](/docs/en/node-ratelimit) |
| Sub-accounts    | The user's sub-accounts on each node (multi-package / routed outbounds create separate credentials)               |
| Nodes           | Nodes the user imported themselves (excluding the package pool), can be cleared                                    |
| Delete          | Delete the user and all credentials                                                                               |

## Subscription token

Each user has a unique subscription token used to authenticate subscription links. It can be regenerated; the old one is invalidated immediately. The "user short code" in the list identifies the user in short links and can be customized with the pencil icon.

## Telegram binding

"Bind" in the Telegram column generates a `/start` command the user sends to the bot to link their Telegram; afterwards the Mini App shows their package and subscription without a login, see [Telegram Bot](/docs/en/tool-mmwx-tgbot).

## Traffic and multiple packages

List usage aggregates all of the user's billable credentials while the list limit still comes from the primary package. Open "Manage Packages" to see each instance's own usage and limit; the same node uses independent credentials, reset baselines and expiry per instance. Billing formulas and the "Traffic" page details: [Traffic Accounting](/docs/en/traffic-accounting).

## Authentication

The API uses JWT:

- Obtain a JWT token after login
- Send it in the MM-Authorization header
- Log in again after expiry
