妙妙屋X 同时提供服务器容量、Xray 节点原始流量和用户套餐计费流量。它们解决的问题不同，数值不要求相等。界面中的 `GB` 按 `1024³` byte 换算。

## 基础口径

服务器原始上行、下行分别记作 `U`、`D`。服务器的统计规则 `M(U,D)` 为：

| 规则   | 公式        |
| ------ | ----------- |
| 双向   | `U + D`     |
| 上行   | `U`         |
| 下行   | `D`         |
| 最大值 | `max(U, D)` |

配置有效重置周期时，服务器当前周期计费用量为 `M(U,D) + 调整量`。调整量包含手工校准、周期起点基线以及不完整历史的对账差额；因此不要把卡片用量与原始上下行再次相加。没有有效重置日时，页面只显示“计数器重置以来计费用量”，不提供周期原始上下行或该等式。

用户计费只使用 Xray 的 user/email 计数器，与服务器选择“系统网卡”或“Xray”无关。采集时会冻结当时的套餐和节点权重：

```text
计费增量 = (原始上行 + 原始下行) × 套餐方向倍率 × 节点倍率
```

套餐“单向”为 `×1`，“双向”为 `×2`；节点倍率默认为 `×1`。历史不会因后来修改倍率而重算。

## 各页面显示规则

| 页面              | 显示值                                 | 数据源与范围                                                                                                                                                                                                                                                  |
| ----------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 首页（管理员）    | 总限额、已用、剩余和 30 日趋势         | 当前 KPI 汇总勾选“计入流量统计”的有限额服务器，按各服务器数据源、规则和调整量计算；不限量服务器单列。开启外部订阅同步后，当前 KPI 再合并外部额度和用量。趋势包含所有已勾选服务器（含不限量），使用日增量和服务器规则，但不含调整量或外部订阅。                |
| 首页（普通用户）  | 所有有效套餐实例的总用量、总额度和趋势 | 当前 KPI 逐套餐实例汇总独立额度和已加权用量；启用同步的外部订阅也会合并。套餐卡片的加权上/下行之和等于该实例用量。趋势由每日总累计快照做相邻日差分，发生重置或缺样时显示断点，并非逐套餐日明细。                                                              |
| 流量信息 · 服务器 | 今日 / 本周 / 本月用量与实时速率       | 日账本按服务器选择的系统网卡或 Xray 数据源汇总，再应用服务器上行、下行、双向或最大值规则。所选日历范围不等于服务器重置周期，且不加入手工调整量。实时上传/下载速率始终来自系统网卡，不受数据源或规则影响。                                                     |
| 流量信息 · 节点   | 节点原始上/下行及节点 → 用户明细       | 只用 Xray 计数器，不应用套餐或节点倍率。物理节点扣除已归属 routed 子节点的部分；routed 节点按其子账号归集。“未归属”用于对齐无法映射到现有用户的流量。                                                                                                         |
| 流量信息 · 用户   | 用户计费上/下行及用户 → 节点明细       | 日账本完整时使用采集时已加权的数据；用户 → 节点明细同样是加权值，反向的节点 → 用户明细是原始值。旧库 `complete=false` 时会回退快照，并按当前套餐倍率估算，可能与采集时权重不同。                                                                              |
| 服务管理          | 服务器当前周期计费用量 / 配额          | 系统网卡源包含所选物理网卡上的全部进出流量；Xray 源汇总该服务器 `node_traffic` 的 inbound/outbound 计数，不等同于做过 routed 归因的节点视图。应用服务器统计规则和调整量，在服务器重置时推进基线。                                                             |
| 节点管理          | 主套餐倍率标记                         | 页面本身不显示独立计费用量。普通用户看到的 `×N` 来自 `users.package_id` 指向的主套餐，不代表其他套餐实例；节点原始流量请到“流量信息 · 节点”查看。                                                                                                             |
| 用户管理          | 用户汇总进度和各套餐实例进度           | 列表用量聚合用户全部计费凭据，但列表限额来自主套餐。打开套餐管理后，每张套餐卡使用该实例自己的基线、额度和已加权用量；多套餐时以实例卡片为准。                                                                                                                |
| 套餐管理          | 计费规则配置                           | 套餐 `×1/×2` 和节点倍率只影响之后采集的增量；总额度修改立即生效。启用单节点额度时会从当前累计建立基线。多套餐实例的总额度与流量独立，单节点额度仍以主套餐兼容路径为准。                                                                                       |
| 订阅文件          | 订阅对应的已用 / 限额                  | 管理员视图汇总选定统计服务器（空为全部）；外部用量只按 `selected_tags` 命中的外部订阅加入，并应用其 upload/download/both 规则。普通用户只返回自己创建的文件：限额取主套餐、用量取该用户全部套餐凭据的计费合计，不合并外部订阅。文件自定义限额可覆盖显示限额。 |

## 公开探针

配置有效重置周期时，节点卡片的“本周期计费用量”与服务管理一致。详情中的“本周期原始上/下行”用于解释数据源，“计费调整”用于完成对账：

```text
本周期计费用量 = 按统计规则处理的原始上/下行 + 计费调整
```

流量趋势默认查看当前计费周期，也可切换“最近 7 日”。若服务器没有有效重置日，则卡片改为“计数器重置以来计费用量”，趋势直接显示最近 7 日。图表展示原始方向流量，不应用服务器统计规则或调整量。实时网速始终来自系统网卡。

“本次开机网卡流量”直接来自 Agent 的 `/proc/net/dev` 累计值，机器重启后重新计数。它不是当前计费周期，也不受服务器数据源、统计规则或手工调整影响。

API 字段和 scope 取值参见[探针 API 字段说明](/docs/probe-api)。

## 对账与排查

1. 先确认比较的是同一时间范围：服务器重置周期、套餐实例周期或今日 / 本周 / 本月。
2. 再确认数据源：系统网卡包含非 Xray 流量，节点和用户视图只统计 Xray。
3. 检查服务器统计规则、套餐 `×1/×2`、节点倍率和手工调整量。
4. 把“本次开机网卡流量”仅用于观察主机网络累计，不用于配额对账。
5. 管理端 `/api/admin/traffic/period` 返回 `complete=false` 时页面会回退旧快照；该区间不应视为完整日账本。公开探针接口没有此字段。

## 外部订阅口径

外部订阅自身提供 upload、download、total 和流量模式。订阅文件管理员视图按该模式选方向；首页当前 KPI 则始终使用 upload + download。两个页面目前不是同一口径，排查时应分别核对，不要直接相减。
