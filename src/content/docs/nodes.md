节点管理 — 上方「导入外部节点」折叠面板，下方节点列表：按协议 / 标签筛选，每行是一个节点及其行内操作

## 概述

节点是入站配置在订阅系统中的映射。每个入站创建后，系统会自动生成对应的节点，用于订阅分发。页面分成两块：

- **导入外部节点**：把机场订阅或单条 URI 导入为「外部节点」
- **节点列表**：所有节点（自建 + 外部），支持按协议、按标签筛选，行内提供编辑 / 落地 / 路由 / 复制 URI 等操作，右上角一排按钮是全局工具

## 节点来源

| 来源           | 说明                       | 同步方式  |
| -------------- | -------------------------- | --------- |
| Xray 入站      | 通过入站向导创建的协议入站 | 自动同步  |
| 远程服务器入站 | 远程服务器上的入站配置     | 自动同步  |
| 外部订阅导入   | 从外部订阅链接导入的节点   | 手动/定时 |

## 添加节点（向导）

点右上角「添加节点」，向导分两步。

### 第一步：选择服务器

![添加节点第一步截图](../../assets/screenshots/add-node-step1-selected.webp)

选择服务器：每台服务器可选 IPv4 / IPv6 作为节点地址，「Xray 就绪」表示可以直接建节点；右侧「转发链」选项卡用于在转发链入口上建节点

如果服务器设置了域名但 443 端口还没有配好证书与 Nginx，会先弹出「SSL 配置」提示。需要 TLS 类协议（Trojan + TLS、Hysteria2、AnyTLS 等）时点「配置」先完成证书；只建 REALITY / Shadowsocks / Snell 等不需要证书的协议可以直接关闭提示继续：

![SSL 配置提示截图](../../assets/screenshots/nodes-add-ssl-prompt.webp)

SSL 配置提示：列出 443 端口尚不可用的服务器，可一键配置

### 第二步：配置入站参数

![添加节点第二步截图](../../assets/screenshots/nodes-add-vless-reality.webp)

配置入站参数：协议 → 传输协议 → 安全协议 → 配置模式 → 节点名称 → 协议特定配置 → 用户；右侧 JSON 预览随选项实时更新

| 区域           | 说明                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| 选择协议       | SHADOWSOCKS / SHADOWSOCKS2022 / SOCKS5 / TROJAN / VLESS / VMESS / HYSTERIA2 / ANYTLS / HTTP / SNELL / MIERU     |
| 传输协议       | 随协议变化，如 VLESS 可选 GRPC / TCP / WSS / XHTTP                                                             |
| 安全协议       | REALITY / TLS / XTLS-Vision / XTLS-Vision-REALITY / ENC 等，可用组合见 [协议矩阵](/docs/protocol-matrix)        |
| 配置模式       | 简易模式：端口、UUID / 密码全部自动生成；专家模式：可改端口、监听地址、嗅探、中转地址等高级参数                  |
| 节点名称       | 显示在列表和订阅中的名称，国旗按服务器 IP 自动添加                                                              |
| REALITY 域名   | 自动从域名池探测延迟最低的目标域名，也可手动填写并「探测」；「防止 Reality 被盗用」会创建专用 Tunnel 只放行 serverNames |
| 用户管理       | 默认为当前管理员，UUID / 密码 / PSK 自动生成，可添加多个用户                                                   |
| JSON 预览      | 实时生成的入站配置，提交前可核对                                                                               |

点「提交配置」后，主控在服务器上创建入站、同步节点并提示「创建完成」。各协议向导的截图与参数说明见 [协议参考](/docs/protocol-matrix) 下的各协议页面。

## 导入外部节点

展开页面顶部的「导入外部节点」面板，有三个选项卡：

![导入外部节点面板截图](../../assets/screenshots/nodes-import-panel.webp)

导入外部节点：手动输入 / 订阅导入 / SOCKS5 三种方式，以及节点标签、跳过证书验证、启用中转等选项

### 手动输入

把 `vmess://`、`vless://`、`trojan://`、`ss://`、`anytls://`、`hysteria2://` 等 URI 每行一条粘贴进去，点「解析节点」预览，再点「保存节点」入库：

![手动输入 URI 截图](../../assets/screenshots/nodes-import-manual.webp)

手动输入：每行一条 URI

![解析结果截图](../../assets/screenshots/nodes-import-manual-parsed.webp)

解析后先预览节点名 / 协议 / 地址，确认无误再保存；保存后节点带「手动输入」标签并标记为「外部」

### 订阅导入

填入机场的 Clash 订阅链接，选择 User-Agent（默认 clash.meta），可选填节点标签，点「导入节点」后系统会拉取并解析订阅里的全部节点；导入过的订阅会出现在「订阅管理 → 外部订阅」里，可用「同步外部订阅」定时刷新。

![订阅导入截图](../../assets/screenshots/nodes-import-subscription.webp)

订阅导入：订阅链接 + User-Agent + 节点标签

### SOCKS5

直接填写地址、端口、用户名密码，导入一个 SOCKS5 出口，常用于落地。

## 自动同步

当入站配置发生变更时，系统通过事件总线自动触发节点同步。同步过程会将入站配置转换为 mihomo/Clash 兼容的代理节点格式。

同步触发条件：

- 创建新入站
- 修改入站配置
- 删除入站
- 远程服务器入站变更

## 端口转发

### 隧道配置

#### 链式隧道

使用多台 Agent 服务器转发选择的落地节点，或手动填写目标地址与端口。

#### 端口转发

将一台 Agent 的端口转发到选择的落地节点，或手动填写目标地址与端口。

### 中转配置

中转配置不会在妙妙屋X中处理转发。该功能通常用于已经配置外部转发的场景，再将转发配置添加到节点中使用。

## URI 管理

在这里可以查看所有用户、所有节点的 protocol:// URI 配置。

## 节点流量与倍率

节点列表里的 `×N` 是普通用户主套餐(`users.package_id`)对该节点的计费倍率，不是节点自身流量，也不代表该用户的其他套餐实例。节点原始上/下行在“流量信息 · 节点”中查看；用户计费流量还会叠加套餐方向倍率。详见[流量统计口径](/docs/traffic-accounting)。

## 排序模式

开启后，可以拖动节点或点击快速移动按钮调整排序；关闭排序模式后保存排序结果。

## Tunnel(任意门转发)管理

Tunnel(dokodemo-door)入站用于把一台服务器某端口的流量转发到另一目标(已有节点或固定地址),常用于「入口机中转落地机」等链式加速。Tunnel 入站本身不进节点列表,统一在节点管理顶部的「Tunnel 管理」入口里查看、添加与删除(跨所有远程 / 分享服务器聚合)。

![Tunnel 管理对话框截图](../../assets/screenshots/nodes-toolbar-tunnel.webp)

Tunnel 管理：隧道配置 / 中转配置 / 链式转发 / 端口转发四个选项卡

### 添加 Tunnel(两种模式)

在「Tunnel 管理」里添加,或添加入站时选择 Tunnel 协议。转发目标有两种给法:

### ① 转发已有节点(推荐)

添加入站时选择 Tunnel 协议,再选「转发已有节点」,会自动按所选节点填好转发地址 / 端口 / 网络类型等。创建后会自动生成一个配套节点:名称为「原节点名 | Tunnel」,入站标识为该 tunnel 的 tag,clash 配置克隆原节点,但服务器地址与端口改为 tunnel 服务器的 IP 与监听端口——这样客户端连 tunnel 服务器即走转发链路。

### ② 端口转发(转发到固定目标)

直接填目标地址与端口(不依赖已有节点),把 tunnel 服务器某监听端口的流量原样转发到该目标。适合转发任意落地(非面板节点)或自建链路。可勾选同时转发 UDP —— 游戏 / 语音需要,否则 UDP 会被直接丢弃。

### 端口转发复用模式(按域名 / IP 分流)

在「Tunnel 管理 → 端口转发」里,可以复用一个已有的 tunnel 入站,只把指定的域名 / IP 从该入站转走 —— 底层是给该入站加一条 routing 规则 + 一个 freedom 出站,而不是新开监听端口。

这类规则在「路由」面板里带黄色「端口转发」标记;删除请回到「Tunnel 管理」列表操作,不要在路由面板直接删,以免留下孤立出站。

### 切换节点的服务器地址(中转)

节点列表里每个节点的「服务器地址」都可以「切换」到一个中转入口:把该节点 clash 配置里的 server / port 改成某台 tunnel 服务器的入口地址与端口,客户端就改走中转链路,而原落地地址会被保存为「原服务器」。

用「端口转发」模式配好一条到某落地节点的转发后,妙妙屋X 会自动把该落地节点的地址切到 tunnel 入口(entryHost:监听端口),省去手动切换;自动切换失败不影响转发本身,可再手动切。

已中转的节点在「服务器地址」下方会多一行「原服务器」,点击可编辑或回退到原始地址。

### 「被 tunnel 转发」标识

若某节点正被某个 tunnel 转发,它在节点列表里会显示一个「被 tunnel 转发」标签,鼠标悬停可看到是哪台服务器的哪个 tunnel。

Tunnel 管理为管理员功能;对接收到的分享服务器同样可用。删除 tunnel 会一并清理其配套节点。

## 转发链（转发管理）

除了基于 Xray 任意门的 Tunnel，妙妙屋X 还提供由 Agent 原生实现的「转发管理」：在「转发管理」页面用拖拽把服务器编排成「入口 → 中转 → 出口」的转发链，末端可以直接落到一个落地代理节点；添加节点向导的第一步里也能直接选「转发链」作为节点入口。

![创建转发链对话框截图](../../assets/screenshots/forward-create-dialog.webp)

创建转发链：从右侧拖服务器到入口 / 中转 / 出口组，出口二选一（拖服务器落地或选落地节点）

## 注意事项

- 由入站自动生成的节点，修改入站后会自动更新
- 手动修改节点名称不会被自动同步覆盖
- 禁用的节点不会出现在任何订阅输出中
- 节点解析为 IP 后可一键「恢复域名」,恢复的是解析前的原始域名(不影响节点所属服务器)
- 新建节点默认使用所属服务器名作为标签,便于按服务器分类筛选;已有的「手动输入」等历史标签保持不动
